## Product decisions (locked 2026-04-30 — 2026-05-01)

1. **Source asset is `assets/icon/app_icon.png`** — already present on this branch (1024×1024 RGB PNG, no alpha). Add it to git as part of the planning commit (the implementing agent does NOT need to add it).
2. **Tooling: `flutter_launcher_icons`** — Flutter community standard, regularly maintained, generates all required Android mipmap sizes and the full iOS `AppIcon.appiconset`.
3. **No adaptive icons** in this PR. The default `image_path` config produces standard square icons that work across all Android versions. Adaptive icon foreground/background customization is deferred — current behavior is acceptable for closed testing.
4. **iOS alpha channel stripped** (`remove_alpha_ios: true`) — Apple rejects icons with alpha.

## Scope — file-by-file

### 1. **NEW (committed by lead in this planning commit)** — `assets/icon/app_icon.png`

The 1024×1024 square master. The implementing agent uses this as the source. **Do NOT replace, resize, or modify this file.**

### 2. `pubspec.yaml`

Two additions:

**Add to `dev_dependencies` block:**
```yaml
flutter_launcher_icons: ^0.14.x   # latest stable major; agent picks exact version from pub.dev
```

**Add a top-level `flutter_launcher_icons:` configuration block** (anywhere after the `flutter:` block; standard convention is at the end of the file):
```yaml
flutter_launcher_icons:
  android: true
  ios: true
  image_path: "assets/icon/app_icon.png"
  remove_alpha_ios: true
```

**Do NOT** change `name`, `version`, `description`, or any other dependency.

### 3. Run icon generation

After `flutter pub get`, run:
```bash
dart run flutter_launcher_icons
```

This regenerates:
- `android/app/src/main/res/mipmap-mdpi/ic_launcher.png` (48×48)
- `android/app/src/main/res/mipmap-hdpi/ic_launcher.png` (72×72)
- `android/app/src/main/res/mipmap-xhdpi/ic_launcher.png` (96×96)
- `android/app/src/main/res/mipmap-xxhdpi/ic_launcher.png` (144×144)
- `android/app/src/main/res/mipmap-xxxhdpi/ic_launcher.png` (192×192)
- All 18 PNGs under `ios/Runner/Assets.xcassets/AppIcon.appiconset/`
- `ios/Runner/Assets.xcassets/AppIcon.appiconset/Contents.json` (regenerated by the tool)

**Commit all the regenerated files.** Do not exclude any.

## Risks

- **`flutter_launcher_icons` is a code-generator that overwrites tracked PNGs.** Re-running it should be deterministic — same input produces same output. The PR diff will show large binary file changes for all 23 icon files; that is expected.
- **iOS alpha channel** — if the source PNG has any alpha, `remove_alpha_ios: true` flattens it. The current source is RGB (no alpha) so this is a safety net, not strictly needed.
- **CocoaPods may regenerate `Podfile.lock`** during `flutter pub get`. If it does, include the change in this PR.
